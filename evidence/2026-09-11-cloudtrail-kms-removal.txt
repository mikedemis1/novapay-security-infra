2026-09-11 - CloudTrail CMK removed (NEXT-STEPS.md step 1, SECURITY_DECISIONS.md
"2026-09-11 - The CloudTrail CMK is dropped instead of fixed")

Code changes applied before any AWS call:
- infra/cloudtrail.tf: removed `kms_key_id = aws_kms_key.cloudtrail_logs.arn` from
  aws_cloudtrail.org_trail; bucket default encryption
  (aws_s3_bucket_server_side_encryption_configuration.cloudtrail_logs) set back
  to sse_algorithm = "AES256" (was "aws:kms").
- infra/kms.tf: removed `prevent_destroy` from aws_kms_key.cloudtrail_logs only.
  The trail's own prevent_destroy (cloudtrail.tf) and the bucket's were not
  touched.

  # aws_s3_bucket.cloudtrail_logs will be updated in-place (tags_all drift only)

      - kms_master_key_id = "arn:aws:kms:eu-west-1:771665904432:key/83146099-de2f-4351-b4e7-675165a648b2" -> null

had already shown (no KmsKeyId on the trail, AES256 on live log objects).

Result: the key is scheduled for permanent deletion on 2026-09-18. It can be
cancelled with `aws kms cancel-key-deletion` up to that date if this decision
needs to be reversed. The aws_kms_key.cloudtrail_logs and aws_kms_alias.cloudtrail_logs
resource blocks remain in infra/kms.tf (same pattern as the already wound-down
aws_kms_key.app_data): a plain, untargeted `terraform apply` in this repository
would try to recreate them, so any future apply here must keep excluding these
two resources until the code itself is deleted or the decision is reversed.
